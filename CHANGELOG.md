# Changelog

All notable changes to the ArchLens project will be documented in this file.

## [Unreleased]

### Added
- **Dependencies and known vulnerabilities:** reads `requirements*.txt`, `pyproject.toml`, `package.json` (+ lockfile) and `go.mod` from the repository root, lists direct dependencies as pinned or not, and checks pinned versions against OSV.dev with severity, advisory link and the version to upgrade to. Shown on the report page, in the JSON API (`dependency_scan`), the Markdown export and the CLI; stored in a new `metrics.dependencies_json` column (migration `a1c5e8f20b64`). OSV or GitHub trouble degrades to "couldn't check", never a failed analysis. The score formula is unchanged. See `docs/walkthroughs/01-dependency-vulnerabilities.md`.
- `docs/roadmap.md` now records the decision to build three features and why the other ideas were dropped or deferred.
- **Live progress:** `POST /api/v1/analyze/stream` streams an analysis's progress as newline-delimited JSON (`validate`, `reuse`, one `fetch` event per finished GitHub call, `analyze`, `score`, `save`, then `done` or `error`). The home page's "How it works" steps light up from these events; without JavaScript the form posts as before.
- **Evidence for every point:** each dimension on a report opens to show its checks (passed, partial, missing, given, not scored) with the scorer's own finding or the files the check looks for, and the points earned. `app/services/evidence.py` rebuilds this from stored reports; a test runs the real scorer over about 900 generated repositories to prove every dimension adds up.
- **Fixes with points:** "What to fix first" ranks every missing check by the points it adds (exact for files, "up to" for banded checks), projects the score and grade after the exact fixes, and copies as a Markdown checklist. The Markdown export includes the same list.
- **Charts:** score gauge, radar chart of the dimension profile (overlaid for two repositories on the compare page), language bar in GitHub's colours, the split of the 100 points on the home and scoring pages, and a score history when a repository has several reports.
- **Report facts:** last push (days before the scan) and the number of CI workflows join stars, forks, issues, contributors, size and languages.
- **History filters:** search by name, filter by profile, sort by date, score or name, with filters kept across pages.
- **README badge snippets** as Markdown, HTML or image URL; an "Analyze again" banner on live reports older than the reuse window.
- **Process flows:** `docs/process-flows.md` documents every user and system flow with diagrams, files, functions and error paths.
- **README badge:** `GET /badge/{owner}/{repo}.svg` shows the latest stored grade and score (or "not analyzed"). It reads the database only and never calls GitHub; responses are cacheable for an hour (five minutes when there is no report). Report pages include a copyable Markdown snippet.
- **Compare:** `/compare?a=owner/repo&b=owner/repo` shows two reports side by side with per-dimension differences. Stored reports are reused; anything new goes through the normal reuse window and rate limit, and invalid input is rejected before any analysis runs.
- **How scoring works:** `/scoring` lists every check, the files it looks for and its points per profile, generated from the scorer's constants. Tests run the real scorer against the page's numbers.
- **Markdown export:** download a report from its page (`/analysis/{id}/report.md`) or fetch it from `GET /api/v1/analyses/{id}/markdown`.
- **About page** with the architecture, tech stack, design decisions and limitations, and `/repo/{owner}/{repo}`, a stable link to a repository's newest report.
- **Report actions:** copy link, copy as Markdown and compare buttons.
- **Example reports:** an empty database is filled on startup with real analyses of `psf/requests`, `pallets/flask` and ArchLens (`app/seed/examples.json`, regenerated by `scripts/build_examples.py`). They are labelled as examples with their capture date.
- **Demo quota protection:** a report of the same repository and profile from the last hour is reused instead of calling GitHub again, and each client can start 5 new analyses per 10 minutes (`429` with `Retry-After`).
- **Input:** the form and API accept `owner/repo` as well as full URLs; one-click example chips fill the form.
- **Pages:** an HTML 404 page for unknown routes (the API keeps JSON), a favicon, page descriptions and Open Graph tags, and a footer with author and project links.
- **Renamed repositories:** when GitHub follows a rename or transfer, the old name is stored in a new `repository_aliases` table (Alembic migration), so the old name's permalink, badge, reuse window and compare check find the report under the new name.
- **"Analyze again" runs live:** a report's "Analyze again" and "Run a fresh analysis", and the 404 page's "Analyze owner/repo", open the home page with the form filled in and start the streamed analysis there (only when the link comes from ArchLens itself).
- **Deployment:** `render.yaml` pins the Singapore region; `requirements-dev.txt` holds test and lint tools so they are not installed in the Docker image; CI smoke-tests the built container.

### Changed
- **Design:** the original dark glass design, refined: the same indigo-to-emerald brand, Plus Jakarta Sans / Inter / JetBrains Mono, glass cards, gauge, metric tiles and dimension colours, now built on colour tokens with a matching light theme that follows the system setting until a visitor picks one. One set of inline SVG icons, toasts, tabs, menus, tooltips and empty and error states. Text meets WCAG AA contrast in both themes and every page fits a 360 px screen without sideways scrolling. Removed decorative blobs, the floating preview animation, gradient headline text and the "Repository Intelligence Engine" label.
- The home page leads with what ArchLens does, keeps the stored-report preview, and adds client-side validation that matches the server; the navigation becomes a menu on small screens.
- HTML pages are left out of the OpenAPI schema; API endpoints are grouped as Analyses, Reports, Badges and System.
- Scoring point values, thresholds and file names are now named constants in `metrics_service.py`; scores are unchanged.
- Page JavaScript moved into `app/static/js/site.js`.
- `render.yaml` sets `FORWARDED_ALLOW_IPS=*` so links built behind Render's proxy use `https://`.
- One shared `httpx.AsyncClient` is opened at startup and closed on shutdown, so the six GitHub calls of an analysis run concurrently over pooled connections.
- Repository URLs are normalised to `https://github.com/{owner}/{repo}` (case, trailing slash, `.git`, `www.`), so the same repository is stored once.
- The home page previews a stored report instead of a static mock-up and keeps the typed URL after an error.
- Results show large counts compactly (54.6k) and the score first on small screens; history rows are links.
- The live pipeline marks a reused report's steps as reused (not done), says why a step failed ("Repository not found", "GitHub did not answer") and announces a slow GitHub after four seconds; the active step's spinner is a true circle.
- An analysis that fails because GitHub is down or out of quota no longer uses up one of the visitor's analyses, and when one of the six GitHub calls fails, the others are cancelled instead of spending quota.
- Key strengths and areas of concern are shown side by side again, as in the first design (concerns first on phones); radar and languages share the column beside "What to fix first"; the badge snippets use the report's profile.
- Primary buttons use the brand's indigo-to-cyan gradient again, in a version with AA contrast for white text.
- The history table shows the date and UTC time again, with the relative time underneath; its count follows the instant filter.
- The compare page says whether it is loading stored reports or analyzing on GitHub, and marks which repository field an error is about; the comparison sentence names which repository each number belongs to.
- The scoring page's points split is one proportional bar at every width, with a legend.
- FastAPI's minimum version is 0.118, the first that keeps request-scoped dependencies open until a streamed response finishes.

### Fixed
- GitHub errors other than 404 or a 403 rate limit (an empty repository's 409, 429 rate limits, a rejected token) returned a bare 500; they now map to clear messages and status codes (422, 503, 502).
- `repo_type` values outside `library`, `personal` and `enterprise` were accepted.
- The executive summary produced garbled sentences ("readme. and ... file..") and used different score tiers from the results page.
- Going Back to the home page after an analysis left the Analyze button disabled.
- The theme button was labelled with the current theme ("Dark Mode") rather than the one it switches to.
- The hero form squeezed the URL field to a few characters at desktop widths.
- `alembic/env.py` did not import the models, so autogenerate saw an empty schema.
- `archlens analyze owner/repo`, the documented CLI command, failed with "Got unexpected extra argument": Typer folded the single command into the app. `analyze` is a real subcommand again.
- Report score history rows without an Example tag stretched the grade badge across the bar.
- Pages scrolled sideways at 1024 to 1100 px because the header tooltips overflowed the window.
- Fact-tile labels overflowed their tiles at 1280 to 1440 px; "Last push" left out the year for older pushes.
- Templates showed an invented "C" grade for reports stored without one; they now show the grade the score maps to (the API and badge too).
- Server errors (429, 502, 503) marked the repository field as invalid although the input was fine.
- On phones, the GitHub request list and the findings tabs were clipped, and several tap targets were under 40 px.

## [1.0.0] - 2026-07-25

### Added
- **Command Line Interface (CLI):** Introduced the `archlens` global executable CLI tool using Typer and Rich console formatting.
- **Glassmorphic Hero Section:** Rebuilt the landing page layout to support a two-column glassmorphic hero design with modern animations.
- **Security & Privacy Policy:** Added a dedicated section detailing how the platform interacts safely with GitHub via read-only APIs without cloning code.
- **CI/CD Integration:** Created GitHub Actions workflow for automated testing and code quality checks.
- **Git Hooks:** Configured `pre-commit` configuration for automated formatting and checking.

### Fixed
- **Redirect Bug:** Fixed `301 Moved Permanently` exception raised by `httpx` during API requests to renamed GitHub repositories.
- **Light/Dark Mode Theme Toggle:** Fixed theme toggle and ensured support for light mode across all pages.
- **Layout Bugs:** Fixed footer overlapping issues on the results and history pages.
